================================================================================
1. PROJECT OVERVIEW
================================================================================

ResumePard is an AI-powered Resume-Job Description matching system that helps 
HR professionals and recruiters automatically:

✓ Parse resumes from multiple formats (PDF, DOCX, TXT)
✓ Analyze job descriptions
✓ Match candidates to job requirements
✓ Rank candidates intelligently
✓ Provide detailed analytics and recommendations

The system uses Natural Language Processing (NLP) with spaCy, pattern matching,
and sophisticated scoring algorithms to evaluate candidate-job fit.

2. COMPLETE WORKFLOW
================================================================================

THE 4-STEP PROCESS:
-------------------

Step 1: JOB DESCRIPTION ANALYSIS
    ↓
Step 2: RESUME PARSING
    ↓
Step 3: MATCHING & SCORING
    ↓
Step 4: RANKING & ANALYTICS


DETAILED WORKFLOW:
------------------

STEP 1: Job Description Processing (jd_processor.py)
-----------------------------------------------------
Input: Job Description Text

Process:
→ Extract Required Skills (e.g., Python, AWS, React)
→ Extract Preferred Skills (e.g., Docker, Kubernetes)
→ Parse Experience Requirements (e.g., "3+ years")
→ Parse Education Requirements (e.g., "Bachelor's degree")
→ Categorize Priority (Required vs Preferred)

Output: Structured JD Data
{
    "required_skills": [...],
    "preferred_skills": [...],
    "experience_requirements": {...},
    "education_requirements": {...}
}


STEP 2: Resume Parsing (info_extractor.py + text_extractor.py)
---------------------------------------------------------------
Input: Resume Files (PDF/DOCX/TXT)

Process:
→ Extract Text from file (handle different formats)
→ Extract Contact Info (email, phone, LinkedIn)
→ Extract Name (using NLP - Named Entity Recognition)
→ Extract Skills (match against 50+ known skills)
→ Extract Experience (work history, years)
→ Extract Education (degrees, universities)
→ Extract Projects (project descriptions)

Output: Structured Resume Data
{
    "name": "John Doe",
    "contact_info": {
        "email": "john@example.com",
        "phone": "+1234567890",
        "linkedin": "linkedin.com/in/johndoe"
    },
    "skills": ["Python", "AWS", "SQL", ...],
    "experience": ["Job 1 description", "Job 2 description", ...],
    "education": ["Bachelor's in CS", ...],
    "projects": ["Project 1 description", ...]
}


STEP 3: Resume-JD Matching (resume_matcher.py)
-----------------------------------------------
For Each Resume:

1. Compare Resume Skills ↔ JD Required Skills
   - Direct matching: "Python" = "Python"
   - Fuzzy matching: "React.js" matches "React"
   
2. Compare Resume Skills ↔ JD Preferred Skills
   - Same matching logic as required skills
   
3. Compare Experience ↔ JD Experience Requirements
   - Extract years from resume (e.g., "2020-2023" = 3 years)
   - Check if meets minimum requirement
   - Check for technology-specific experience
   
4. Compare Education ↔ JD Education Requirements
   - Check degree level (Bachelor's, Master's, PhD)
   - Check field of study relevance
   
5. Analyze Projects ↔ JD Skills
   - Count JD skills mentioned in project descriptions
   
6. Calculate Weighted Scores
   - Apply weights to each component
   
7. Generate Overall Match Score (0-100%)
   - Combine all weighted scores
   - Add differentiation factors


STEP 4: Candidate Ranking (candidate_ranker.py)
------------------------------------------------
For All Candidates:

1. Apply additional scoring metrics:
   - Skill diversity
   - Experience quality
   - Education level
   - Project relevance
   
2. Calculate Final Ranking Score
   - Combine base match with additional metrics
   
3. Sort by Score (Highest → Lowest)
   - Primary: Final score
   - Secondary: Base match score
   - Tertiary: Required skills matched
   
4. Assign Ranks (1, 2, 3, ...)
   
5. Generate Analytics & Visualizations
   - Charts, graphs, insights

3. SCORING SYSTEM - COMPLETE BREAKDOWN
================================================================================

LEVEL 1: BASE MATCH SCORE (resume_matcher.py)
----------------------------------------------

These weights determine how the initial match score is calculated:

WEIGHTS:
    Required Skills:    40%  ← Most important!
    Preferred Skills:   15%  ← Nice to have
    Experience:         25%  ← Work history match
    Education:          10%  ← Degree requirements
    Projects:           10%  ← Project relevance
                       ----
    TOTAL:             100%


EXAMPLE CALCULATION:
Resume A vs Job Description:

├─ Required Skills Match: 80% × 0.40 = 32.0 points
├─ Preferred Skills Match: 60% × 0.15 = 9.0 points
├─ Experience Match: 90% × 0.25 = 22.5 points
├─ Education Match: 100% × 0.10 = 10.0 points
└─ Projects Match: 70% × 0.10 = 7.0 points
                                 ─────────
                 Total Match Score = 80.5%


LEVEL 2: FINAL RANKING SCORE (candidate_ranker.py)
---------------------------------------------------

After base matching, additional factors are considered:

RANKING WEIGHTS:
    Overall Match Score:   50%  ← The base match score
    Skill Diversity:       15%  ← Breadth of skills
    Experience Quality:    20%  ← Quality of experience
    Education Level:       10%  ← Education background
    Project Relevance:      5%  ← Project quality
                          ----
    TOTAL:                100%


HOW EACH COMPONENT IS SCORED:
------------------------------

1. REQUIRED SKILLS MATCH (40% weight)
--------------------------------------
Formula:
    Score = (Matched Skills / Total Required Skills) × 100

Example:
    JD Required: [Python, AWS, SQL, Docker, React]  (5 skills)
    Resume Has: [Python, AWS, SQL, JavaScript]
    Matched: [Python, AWS, SQL]  (3 matches)
    Score = 3/5 = 60% × 0.40 = 24 points

Fuzzy Matching Rules:
    - "React.js" matches "React"
    - "Python3" matches "Python"
    - "JavaScript" matches "JS"
    - Partial matches count (e.g., "Node.js" in "Node.js Developer")


2. PREFERRED SKILLS MATCH (15% weight)
---------------------------------------
Same logic as required skills, but lower weight.
Missing preferred skills won't hurt as much as missing required skills.

Example:
    JD Preferred: [Kubernetes, Jenkins]  (2 skills)
    Resume Has: [Kubernetes]
    Matched: [Kubernetes]  (1 match)
    Score = 1/2 = 50% × 0.15 = 7.5 points


3. EXPERIENCE MATCH (25% weight)
---------------------------------
Two Components:

A) Years of Experience (70% of experience score)
   - Extracts years from resume dates
   - Examples: "2020-2023" = 3 years, "2020-Present" = 4 years (as of 2024)
   - Checks if meets JD minimum requirement

B) Technology Experience (30% of experience score)
   - Checks if specific technologies mentioned in work experience
   - Example: "Worked with AWS" matches "AWS experience required"

CALCULATION:
    JD Requires: 3+ years, AWS experience
    Resume Has: 5 years total, mentions AWS in work history
    
    Years: Meets requirement → 70% = 0.7
    Tech: AWS found → 100% = 0.3
    Score = (0.7 + 0.3) × 0.25 = 25 points

If Requirements Not Met:
    Resume Has: 2 years (less than 3)
    Years: Does not meet → 0% = 0
    Tech: AWS found → 100% = 0.3
    Score = (0 + 0.3) × 0.25 = 7.5 points


4. EDUCATION MATCH (10% weight)
--------------------------------
Two Components:

A) Degree Match (60% of education score)
   Scoring:
   - PhD/Doctorate:     100%
   - Master's/MBA:      80%
   - Bachelor's:        60%
   - Diploma/Cert:      40%
   - Any education:     10%

B) Field Match (40% of education score)
   - Degree in relevant field? (e.g., Computer Science)
   - Relevant fields: CS, Engineering, IT, Software, etc.

EXAMPLE:
    Has Bachelor's in Computer Science:
    Score = 0.6 (Bachelor's) + 0.4 (CS field) = 100% × 0.10 = 10 points

    Has Bachelor's in History:
    Score = 0.6 (Bachelor's) + 0.0 (not relevant) = 60% × 0.10 = 6 points


5. PROJECTS MATCH (10% weight)
-------------------------------
Formula:
    Score = (JD Skills Mentioned in Projects / Total JD Skills) × 100

EXAMPLE:
    JD Skills: [Python, React, MongoDB, AWS, Docker]
    Projects mention: [Python, React, MongoDB]
    
    Score = 3/5 = 60% × 0.10 = 6 points


6. SKILL DIVERSITY (15% of final ranking)
------------------------------------------
Measures breadth of skills across categories:

Skill Categories:
- Programming Languages (Python, Java, JavaScript, C++, etc.)
- Web Frameworks (React, Django, Angular, Flask, etc.)
- Databases (SQL, MongoDB, PostgreSQL, Redis, etc.)
- Cloud Platforms (AWS, Azure, GCP)
- DevOps Tools (Docker, Kubernetes, Git, CI/CD, Jenkins)
- Data Science (ML, TensorFlow, PyTorch, Pandas, etc.)
- Soft Skills (Communication, Leadership, Teamwork, etc.)

Formula:
    Score = (Categories Covered / Total Categories) × 100

EXAMPLE:
    Resume has skills in 4 out of 7 categories:
    - Programming: Python, JavaScript ✓
    - Web Frameworks: React, Django ✓
    - Databases: SQL, MongoDB ✓
    - Cloud: AWS ✓
    - DevOps: None ✗
    - Data Science: None ✗
    - Soft Skills: None ✗
    
    Score = 4/7 = 57% × 0.15 = 8.6 points


7. EXPERIENCE QUALITY (20% of final ranking)
---------------------------------------------
Analyzes experience descriptions for quality indicators.

Quality Keywords (Base Score):
    ["led", "managed", "developed", "designed", "implemented",
     "created", "improved", "optimized", "launched", "delivered",
     "architected", "built", "established", "coordinated", 
     "supervised", "mentored", "collaborated", "executed",
     "achieved", "enhanced", "streamlined"]

Bonuses:
+ Experience variety (multiple job entries)
+ Detailed descriptions (word count)
+ Senior keywords ("senior", "lead", "principal", "manager")
+ Achievement keywords ("increased", "reduced", "saved", "generated")

CALCULATION EXAMPLE:
    Experience text contains:
    - 5 quality keywords → Base 25%
    - 3 job entries → +18.75% (variety bonus)
    - 300 words total → +15% (detail bonus)
    - "Senior Developer" → +2% (seniority)
    - "Improved performance" → +1% (achievement)
    
    Total = 25% + 18.75% + 15% + 2% + 1% = 61.75%
    Score = 61.75% × 0.20 = 12.35 points


8. EDUCATION LEVEL (10% of final ranking)
------------------------------------------
Scoring Scale:
    PhD/Doctorate:              100%
    Master's/MBA/M.S/M.A:       80%
    Bachelor's/B.S/B.A/B.Tech:  60%
    Diploma/Certificate:        40%
    Any education info:         10%

Bonuses:
+ Relevant field (Computer Science, Engineering, etc.): +10%
+ Multiple degrees: +10%

EXAMPLE:
    Bachelor's in Computer Science:
    Base: 60%
    + Relevant field: +10%
    Total = 70% × 0.10 = 7 points
    
    Master's in Business:
    Base: 80%
    + Not relevant field: 0%
    Total = 80% × 0.10 = 8 points


9. PROJECT RELEVANCE (5% of final ranking)
-------------------------------------------
Evaluates project quality and relevance.

Factors:
- Number of projects
- Detail/length of project descriptions
- JD skills mentioned in projects
- Complexity indicators

Complexity Indicators:
    ["architecture", "scalability", "performance", "optimization",
     "integration", "deployment", "microservices", "distributed"]

CALCULATION EXAMPLE:
    3 projects with detailed descriptions mentioning 60% of JD skills:
    
    Base score: 60% (skills match)
    + Project count: +12% (3 projects)
    + Detail level: +8% (good descriptions)
    + Complexity: +3% (complexity terms found)
    
    Total = 60% + 12% + 8% + 3% = 83%
    Score = 83% × 0.05 = 4.15 points

4. MATCH LEVEL CATEGORIZATION
================================================================================

Score ranges are mapped to match levels:

SCORE RANGE       MATCH LEVEL         INDICATOR
───────────────────────────────────────────────
85-100%      →    Excellent Match     🟢 Green
70-84%       →    Good Match          🔵 Blue
55-69%       →    Moderate Match      🟡 Yellow
40-54%       →    Fair Match          🟠 Orange
0-39%        →    Poor Match          🔴 Red

Interpretation:
→ Excellent Match: Strong candidate, highly recommended for interview
→ Good Match: Good fit, worth considering seriously
→ Moderate Match: Decent fit, has potential with some gaps
→ Fair Match: Partial fit, may need training or development
→ Poor Match: Not a good fit for this role

FUZZY SKILL MATCHING:
---------------------

Algorithm:
```
def fuzzy_match(skill1, skill2):
    # Convert to lowercase
    s1 = skill1.lower()
    s2 = skill2.lower()
    
    # Check if one contains the other
    if s1 in s2 or s2 in s1:
        return True
    
    # Check for common variations
    variations = {
        "react": ["reactjs", "react.js", "react native"],
        "python": ["python3", "python2", "py"],
        "javascript": ["js", "es6", "ecmascript"],
    }
    
    for base, variants in variations.items():
        if (base in s1 and any(v in s2 for v in variants)) or \
           (base in s2 and any(v in s1 for v in variants)):
            return True
    
    return False
```

MULTI-RESUME RANKING ALGORITHM:
-------------------------------

Step-by-step process:

1. INITIALIZATION
   - Load job description
   - Parse JD into structured format
   - Initialize candidate list
   - Initialize error list

2. BATCH PROCESSING
   For each resume file:
       Try:
           a) Extract text from file
           b) Parse resume into structured data
           c) Match against job description
           d) Calculate base match score
           e) Calculate additional metrics
           f) Calculate final ranking score
           g) Create candidate object
           h) Add to candidate list
       Catch errors:
           - Add to error list
           - Continue with next resume

3. SORTING
   Sort candidates by multiple criteria:
       Primary: final_ranking_score (descending)
       Secondary: overall_match_score (descending)
       Tertiary: required_skills_matched (descending)
       Quaternary: preferred_skills_matched (descending)
       Final: candidate_name (alphabetical)

4. RANKING ASSIGNMENT
   For index, candidate in sorted_candidates:
       candidate.rank = index + 1
       candidate.percentile = ((total - index) / total) × 100

5. ANALYTICS GENERATION
   Calculate:
       - Score statistics (min, max, avg, median)
       - Match level distribution
       - Skill frequency analysis
       - Gap analysis
       - Category coverage

6. RETURN
   Return:
       - Ranked candidate list
       - Analytics data
       - Processing summary
       - Error report (if any)


TIE-BREAKING LOGIC:
-------------------

When two candidates have the same score:

Level 1: Compare final_ranking_score
    If equal → Go to Level 2

Level 2: Compare overall_match_score
    If equal → Go to Level 3

Level 3: Compare required_skills_matched (count)
    If equal → Go to Level 4

Level 4: Compare preferred_skills_matched (count)
    If equal → Go to Level 5

Level 5: Compare alphabetically by name
    This ensures deterministic ordering

Example:
```
Candidate A: Score 75.5%, 8 required, 3 preferred, Name: "Alice"
Candidate B: Score 75.5%, 8 required, 2 preferred, Name: "Bob"

Result: A ranks higher (more preferred skills)

Candidate A: Score 75.5%, 8 required, 3 preferred, Name: "Alice"
Candidate C: Score 75.5%, 8 required, 3 preferred, Name: "Charlie"

Result: A ranks higher (name comes first alphabetically)
```

FUZZY MATCHING ALGORITHM:
-------------------------

Advanced fuzzy matching for skills:

```
function fuzzy_match(skill_required, skill_in_resume):
    # Normalize
    req = skill_required.lower().strip()
    res = skill_in_resume.lower().strip()
    
    # Exact match
    if req == res:
        return True, 1.0  # Perfect match
    
    # Substring match
    if req in res or res in req:
        return True, 0.9  # Strong match
    
    # Common abbreviations
    abbreviations = {
        "javascript": ["js", "es6"],
        "typescript": ["ts"],
        "python": ["py", "python3"],
        "kubernetes": ["k8s"],
    }
    
    for full, abbrevs in abbreviations.items():
        if (full in req and any(a in res for a in abbrevs)) or \
           (full in res and any(a in req for a in abbrevs)):
            return True, 0.95
    
    # Levenshtein distance (edit distance)
    distance = calculate_levenshtein(req, res)
    max_len = max(len(req), len(res))
    similarity = 1 - (distance / max_len)
    
    if similarity > 0.8:
        return True, similarity
    
    return False, 0.0
```

This ensures:
- "React" matches "React.js", "ReactJS", "React Native"
- "Kubernetes" matches "K8s"
- "JavaScript" matches "JS", "ECMAScript", "ES6"
- Minor typos are tolerated


SCORE NORMALIZATION:
--------------------

Ensures all scores are properly scaled:

```
function normalize_score(raw_score, min_val=0, max_val=1):
    # Ensure score is within bounds
    score = max(min_val, min(max_val, raw_score))
    
    # Apply scaling if needed
    if scale_factor:
        score = score * scale_factor
    
    # Round to 2 decimal places
    score = round(score, 2)
    
    return score
```

Why this matters:
- Prevents scores > 100%
- Handles division by zero
- Maintains consistency
- Enables fair comparisons
